# 로컬 공고 북마크 설계

## 목적

데모 사용자가 관심 있는 공고를 표시하고 다시 빠르게 찾을 수 있게 한다. 북마크는
회사 프로필이나 서버 데이터와 결합하지 않으며, 현재 브라우저에만 저장한다.

## 범위

- 공고 카드마다 북마크 추가·해제 버튼을 둔다.
- 공고함 도구 모음에 `북마크만` 토글을 두어 현재 검색·지역·마감·판정 조건에 맞는
  공고 중 북마크한 항목만 볼 수 있게 한다.
- 추천 영역과 전체 목록에 같은 공고가 동시에 보이면 두 버튼의 상태를 함께 갱신한다.
- 새로고침과 로컬 서버 재시작 뒤에도 북마크를 유지한다.
- 서버 API, SQLite 스키마, 회사 프로필 형식은 변경하지 않는다.

## 저장 방식

`localStorage`의 버전이 붙은 키 `gov-ai-agent:bookmarks:v1`에 공고 ID 문자열 배열을
JSON으로 저장한다. 공고 ID는 서버가 이미 사용하는 `source:source_id` 값이므로 공고를
다시 수집해도 같은 공고를 가리킨다.

저장값이 없거나 JSON이 손상되었으면 빈 목록으로 시작한다. 브라우저 정책 등으로
`localStorage` 읽기·쓰기가 실패하면 예외를 화면 전체로 전파하지 않고 현재 탭의
메모리 상태로 계속 동작한다. 공고가 현재 서버 응답에 없더라도 저장 ID를 임의로
삭제하지 않는다.

## 화면과 상호작용

- 카드 오른쪽에 별 모양의 실제 `button` 요소를 배치한다.
- 해제 상태는 `☆`, 저장 상태는 `★`로 표시한다.
- 버튼은 `aria-pressed`, `aria-label`, `title`로 상태와 동작을 전달한다.
- 별 버튼의 클릭 및 키보드 이벤트는 카드로 전파하지 않아 공고 상세가 함께 열리지
  않게 한다.
- `북마크만` 버튼은 선택 상태를 `aria-pressed`와 시각 스타일로 표시하고 전체 저장
  개수를 함께 보여 준다.
- 북마크만 보기에서 마지막 항목을 해제하면 즉시 목록에서 사라지고 빈 상태를 보여 준다.
- 북마크만 보기의 건수와 판정별 집계는 현재 화면에 남은 공고만 기준으로 다시 계산한다.

## 검증

- 저장값 파싱, 중복 제거, 토글 지속성, 필터 순서, 저장소 오류 대응을 Node 내장
  테스트로 검증한다.
- HTML 스크립트 순서와 접근성·이벤트 연결을 회귀 테스트로 고정한다.
- 기존 Python 회귀 테스트와 JavaScript 문법 검사를 함께 실행한다.
- 실제 브라우저에서 추가, 새로고침 유지, 북마크만 보기, 해제, 카드 열기 비간섭을
  확인한다.
