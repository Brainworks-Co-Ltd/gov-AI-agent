## Problem Statement

목적은 「2026 전남광주 청년 AI 솔버톤」 트랙 B-08에서 **평가를 잘 받는 것**이다.

## What Makes This Cool

**판정 근거를 원문 인용으로 붙인다는 것.** `RequirementVerdict.requirement.quote` 는
LLM이 지어내지 못하도록 공고문 원문 부분문자열 검사를 통과한 것만 남는다
(`agent/eligibility.py:99-109`). "AI가 가능하다고 했다"가 아니라 공고문 몇 항과
회사의 어떤 값을 대조했는지가 표에 뜬다.

판정 자체는 순수 파이썬(`eligibility.py:599-666`)이고 LLM은 문장을 구조로 바꾸기만
한다. 발표 4~5분에서 이것 하나만 제대로 보여줘도 된다.

## Premises

1. **감점 항목을 먼저 없앤다.** 배포 미완은 명시된 감점이고 화면 완성도로 상쇄되지 않는다.
2. **켜둔 채 안 돌려본 LLM이 가장 위험하다.** 키는 들어갔지만 실행 이력이 0이다.
   무대 전에 반드시 한 번 끝까지 돌린다.
3. **발표 4~5분에 세 기능을 다 넣을 수 없다.** 무엇을 버릴지 D가 미리 정한다.

## Recommended Approach

### P0-1. 배포 — Render, 오늘 중

**코드 변경 (2줄)**

```python
PORT = int(os.environ.get("PORT", 8000))              # serve.py:35
# serve.py:360 바인딩 대상에 "0.0.0.0" 추가 (로컬 루프백은 유지)
```

**시작 명령**: `python -m tools.ingest --offline && python serve.py`

`data/app.db` 는 **`.gitignore:6`** 에 걸려 있어 커밋할 수 없다. 대신
`data/notices_cache.json`(추적 중)에서 컨테이너가 매번 DB를 재구성한다.

**API 키는 플랫폼 환경변수로.** `tools/keys.py` 가 `BIZINFO_KEY`·`DATA_GO_KR_KEY` 를,
`tools/hyperclova_api.py:51` 이 `CLOVA_API_KEY` 를 환경변수 우선으로 읽는다.

**Vercel을 쓰지 않는 이유.** 핸들러 모양은 문제가 아니다(Vercel Python 런타임은
`BaseHTTPRequestHandler` 서브클래스를 그대로 받고, `serve.py` 의 `Handler` 가 이미
그 모양이다). 막히는 건 **런타임 파일 쓰기 3곳**이다 — `tools/store.py:104`(SQLite),
`tools/profile_store.py:31`(프로필), `tools/formdoc.py:422`(첨부 캐시). `/tmp` 우회는
상수 3개 환경분기 + 정적 서빙 재구성 + `vercel.json` 이 필요하고, 인스턴스가
재활용되면 판정 캐시가 날아가 **시연 중 재판정 30초 대기**가 걸린다.
`web/` 만 정적 배포하는 것도 불가 — `web/app.js:16` 이 상대경로로 `/api/*` 를 부르므로
껍데기만 뜨고 전부 404가 된다.

**폴백 사다리**: Render → (막히면) **Cloudflare Tunnel** 로 노트북 서버를 공개 URL로
(무료·카드 불필요·5분, 단 대회 후 유지 불가) → 대회 후 Render 재시도.

### P0-2. LLM — 오늘 밤 한 번 끝까지 돌린다

키는 이미 들어갔다(`clova_api_key.txt`). 하지만 **실행 이력이 0이라 켜둔 것과
동작하는 것은 다르다.** 오늘 밤 순서:

1. 시연 후보 공고 2~3건을 **`?refresh=1`** 로 재판정
2. 결과가 규칙보다 나은지 눈으로 확인
3. 나쁘거나 불안정하면 키 파일을 옮기고 규칙으로 확정

**⚠ 판정 캐시는 프로필 해시 기준이다**(`orchestrator.py:59-64`). 키를 넣어도
무효화되지 않는다. **`?refresh=1` 없이 녹화하면 칩은 `연결됨` 인데 표는 정규식
결과인 화면을 찍게 된다.** 이번 계획에서 가장 조용히 죽는 함정.

**켰을 때의 변화**: 요건 추출이 정규식 7개 → LLM(전문 6000자, 최대 12요건). 추출이
늘면 `combine()`(`:661-665`)이 하나라도 `불가`면 `불가`를 반환하므로 **판정이
불가·확인필요 쪽으로 밀린다.** 재시도 로직은 없다(타임아웃 30초, 실패 시 정규식으로 낙하).

### P0-3. 확정된 결함 3개 (B·C)

| 위치 | 문제 | 조치 |
|---|---|---|
| `tools/dedupe.py:188` | `max_tokens=200` 인데 CLOVA v3 `maxCompletionTokens` 하한이 1024. **40번 호출이 전부 400을 받고 조용히 실패** | 1024 이상으로. 한 줄. 지금 통합 25건은 전부 `difflib` 제목 유사도만으로 나온 것 |
| 테스트앱 | `HCX-007`(판정·중복·서식)과 `HCX-DASH-002`(초안) **두 모델이 다 켜져 있어야** 함 | 확인. 하나만이면 절반이 죽음 |
| `bizinfo_key.txt` | **6바이트 = 플레이스홀더** | 기업마당 실수집이 필요하면 발급 |

### P0-4. 골든셋 — 홀드아웃 분리 (B·C)

현재 `data/golden_notices.json` 은 **16건 전부 `*-DUMMY-*`** 이고,
`eligibility.py` 의 규칙들(`_NON_MANUFACTURING`, `_size_bounds`, 이중부정 수정)이
그 16건을 보고 튜닝됐다. 그 숫자는 정확도가 아니라 훈련 데이터 적합도다.

**새로 만들 때 두 가지를 지킨다:**
1. **실제 수집 공고 기반으로.** DB에 999건이 있다. 20~30건을 라벨링하면 발표에서
   *"실제 공고 N건에 대해"* 라고 말할 수 있다. 지어낸 공고로는 그 문장이 안 나온다.
2. **튜닝용과 홀드아웃을 처음부터 나눈다.** 예: 30건 중 20건은 프롬프트 고치면서
   마음껏 보고, **10건은 아무도 안 본다.** 마지막에 한 번만 돌려 그 숫자를 발표에 쓴다.
   **나중에 나누면 이미 다 본 뒤라 홀드아웃이 아니다.**

### P1. 시연 (D)

**시연 공고 2건을 확정한다** — 요건이 실제로 추출되는 것 1건 + 중복 통합된 것 1건
(통합은 25건뿐이라 그 안에서 골라야 함). 확정 전에는 B·C가 요건 추출 프롬프트를
건드리면 안 된다. 시연 화면이 바뀐다.

발표 4:30 배분(초안, 합이 4:30이라 여유 0 — 한 꼭지는 버릴 각오):
문제 0:40 / 공고함·중복통합 0:40 / **판정 요건표+원문인용 1:40** / 초안·점검 1:00 / 기대효과 0:30

### P2. UI (A)

**동결 9.4 12:00.** 그 시점 정의는 "예쁘다"가 아니라 체크리스트다 — 배포 URL에서
4개 탭 정상 렌더 / 시연 3화면 톤 일관 / 콘솔 에러 0. 이후 CSS 동결, 녹화로 전환.

> `11:00~11:45` 가 **AI 멘토단 최종 순회 멘토링(완성도·시연 점검)** 이다. 멘토단이
> 1차 심사 50%다. 그 45분에 보여줄 만한 상태를 만들어 두면 피드백과 관찰평가를
> 동시에 가져간다.

### 녹화

UI 동결(12:00) 후 중식 시간에 촬영. 1분 이내. **배포 URL로 찍는다.**
`?refresh=1` 재판정을 먼저 끝낸 상태여야 한다.

## What I noticed about how you think

- "플랜의 목적이 목업을 실제 web으로 옮기는 것이 아니라 이 대회를 나가는 것이잖아."

- "출처가 어디야?" 일정 표 하나를 그냥 안 받았다. 내가 추론한 부분과 문서에 적힌
  부분을 분리해서 내놓게 만들었다.
