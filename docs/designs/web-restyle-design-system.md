## Problem Statement

`web/` 는 동작하지만 심사위원 눈에 도구처럼 보이지 않는다. 바닐라 730줄(HTML 133 /
CSS 198 / JS 399)에 상단 탭 4개 구조이고, 스타일은 기능 확인 수준에서 멈춰 있다.

같은 백엔드 위에서 3화면 목업(`01-discovery` / `02-eligibility` / `03-draft`)을 만들어
톤을 확인했다. 목업은 승인됐고, 남은 일은 그 톤을 실제 `web/` 로 옮기는 것이다.

## What Makes This Cool

이 화면의 승부처는 예쁨이 아니라 **판정 근거를 보여주는 방식**이다.

요건마다 `RequirementVerdict.requirement.quote`(공고문 원문 인용) / `.company_value` /
`.reason` 세 값이 붙어 있다. `quote` 는 LLM이 지어내지 못하도록 원문 부분문자열 검사를
통과한 것만 남는다(`agent/eligibility.py:99-109`). "AI가 가능하다고 했다"가 아니라
**공고문 몇 조 몇 항과 우리 회사 어떤 값을 대조했는지**가 화면에 그대로 뜬다.
심사에서 설명할 가치가 가장 큰 부분이다.

지금 이 데이터는 4열 표(요건 / 우리 회사 / 판정 / 근거)로 렌더된다. 표를 유지하되
근거 열을 인용 블록으로, 판정 열을 배지로 세워서 같은 정보를 더 읽히게 만드는 것이
이번 작업의 핵심 목표다.

## Premises

1. **디자인 시스템은 신규 제작이 아니라 기존 12개 토큰의 확장이다.** `style.css:5-13` 에
   `--bg --panel --line --text --muted --accent --ok-bg/fg --no-bg/fg --chk-bg/fg`
   12개가 있고, `--ok/--no/--chk` 는 가능/불가/확인필요에 대응한다.
   **이름은 유지하고 값만 교체한다.**
2. **판정 상태는 3개가 아니라 4개다.** `app.js:94` 가 미판정 공고에 `"미판정"` 을 넣고
   `style.css:105` 가 `#eef0f3` 을 하드코딩해 받는다. 토큰을 새로 만들어야 한다.
3. **로직은 건드리지 않는다.** `serve.py` 는 `_STATIC_TYPES` 한 줄만. `app.js` 는
   className 문자열만. fetch·상태·이벤트·DOM 구조는 무수정.
4. **데이터가 없는 요소는 만들지 않는다.** 지원금 표시, 수집 어시스턴트, 사업자번호
   자동조회는 목업에서 걸러냈다.

## Approaches Considered

- **A) 토큰 값만 교체** — 기각. 목업 인상의 절반은 색이 아니라 여백·그림자·정보밀도였다.
  색만 바꾸면 "조금 나아진 현재 화면"에서 멈춘다.
- **C) 목업 역이식** — 기각. 사용자가 프리미티브 계층을 원함. 심사위원이 코드를 열 수
  있고, 그때 설계 의도가 드러나는 구조가 낫다는 판단.
- **B) 토큰 + 프리미티브 3층 재작성** — 채택.

## Recommended Approach

`web/style.css` 를 3층으로 재작성한다.

```
① 토큰       :root — 토큰 30개 (색 26 + radius 2 + shadow 2) + 폰트 스택
② 프리미티브  button .badge .card .field .grid .chip .box   (7종)
             ↑ 새 클래스명을 만들지 않고 **이미 있는 셀렉터**에 붙인다
③ 화면별     .inbox-* .verdict-* .draft-*
```

### 경계 규칙 — 이걸 지키는 게 이 접근의 전부다

1. ②는 ①의 토큰만 참조한다.
2. ③은 ②를 조합한다. **③에서 색 리터럴 금지** — 모든 색은 `var(--...)`.
3. ①에서 기존 12개 토큰의 **이름은 바꾸지 않는다** (기존 규칙이 계속 동작).
4. **한글 modifier 클래스명은 절대 못 바꾼다.** `가능/불가/확인필요/미판정`,
   `오류/경고/정보`, `서식/공고문` 은 백엔드 값이 그대로 클래스가 된다(제약 5).
   BEM 같은 걸로 바꾸려면 `app.js` 에 매핑 함수를 넣어야 하고, 그건 className 수정이
   아니라 로직 추가다. **한글 이름을 그대로 두고 ②의 `.badge` `.issue` `.kind` 를
   베이스 클래스로만 쓴다.**
5. **프리미티브는 새 클래스명을 만들지 않는다.** `button` 은 엘리먼트 셀렉터로
   이미 스타일되고 있고(`style.css:44-46`), 표는 `.grid`(`index.html:71`), 배지는
   `.badge`, 칩은 `.chip` 으로 이미 존재한다. 여기에 붙이면 `index.html` 과 `app.js`
   의 className 을 **거의 안 건드려도 된다** — `app.js` diff 가 0에 수렴하는 게
   목표다.
6. **`v-rows` 표는 `<table>` 로 유지한다.** 목업의 3줄 카드로 바꾸려면 `index.html:71-76`
   의 `<thead>`, `app.js:194-200` 의 행 템플릿, `colspan="4"` 4곳을 전부 고쳐야 한다
   (제약 6). 대신 CSS만으로 판정 열을 배지로, 근거 열을 인용 블록으로 세운다.
   표가 카드보다 못한 것도 아니다 — 요건 8개를 위아래로 훑을 때는 표가 더 빨리 읽힌다.

### 토큰 갭 (12 → 30)

```
유지·값교체(12)  bg panel line text muted accent
                 ok-bg ok-fg no-bg no-fg chk-bg chk-fg
신규(18)         surface-inset border-soft border-hover
                 accent-text accent-selected accent-hover focus-ring text-title
                 ok-border no-border chk-border
                 pending-bg pending-fg pending-border      ← 미판정(제약·전제 2)
                 radius-sm radius-md shadow-card shadow-lift
```

`:root` 밖에 남아 있는 하드코딩 색은 **10곳**이다. 전부 흡수처가 있어야 한다:

| 위치 | 값 | 흡수 토큰 |
|---|---|---|
| `style.css:58` | `#c3c8cf` (버튼 hover 보더) | `--border-hover` |
| `style.css:60` | `#1a4f9f` (primary hover) | `--accent-hover` |
| `style.css:59,68` | `#fff` | `--panel` |
| `style.css:105,144,155` | `#eef0f3` | `--pending-bg` / `--surface-inset` |
| `style.css:109,147` | `#eaf1fb` | `--accent-selected` |
| `style.css:123` | `#fafbfc` (표 헤더) | `--surface-inset` |

hover 두 개(`--border-hover`, `--accent-hover`)가 없으면 "하드코딩 색상값 0개"가
달성 불가능하다. 1차 목록에서 빠져 있던 것들이다.

### 팔레트

검증 완료한 Radix 커스텀 값을 쓴다. 확인된 사항:

- 카드 표면은 `#fff` 고정. `--bg`(`#f4f7ff`, L 0.9297)가 `gray-1`(`#f2f3f9`, L 0.8982)보다
  밝아서, Radix 관례대로 `gray-1` 을 카드에 쓰면 카드가 페이지보다 어두워진다.
- 솔리드 채움에 `gray-9`(`#727eb7`) 금지 — 흰 텍스트 대비 3.90:1로 AA 미달.
  `--accent` 는 `blue-10`(`#445ae6`, 5.45:1).
- 포커스 링은 `blue-9`(`#4f68f5`) — gray 스케일에는 비텍스트 3:1을 넘는 값이 없다.
- 3분류 배지는 step3 배경 + step12 텍스트(10:1 이상). Radix 기본 step11은 이 배경에서
  4.5:1을 아슬하게 미달한다.

### 폰트

Pretendard woff2를 `web/` 에 두고 `serve.py:38-40` `_STATIC_TYPES` 에
`".woff2": "font/woff2"` 한 줄 추가. `@font-face` 는 `style.css` 상단에.
제약 1과 2를 동시에 만족한다.

**기본값: 전체 woff2(~1.2MB)를 그대로 커밋한다.** 서브셋은 `fonttools` pip 설치가
필요해서 제약 3과 충돌한다. 1.2MB는 로컬 서빙이라 체감 지연이 없고, 저장소 용량도
문제될 크기가 아니다. 서브셋은 시간이 남을 때의 선택 사항으로 둔다.

### app.js 편집 경계

className 문자열만 고친다. 경계 규칙 4·5가 이 경계를 실제로 지킬 수 있게 만든다
(한글 modifier 유지 + 표 구조 유지). 커밋 전에 `git diff web/app.js` 를 읽어서
className 외의 변경이 없는지 확인한다.

## Open Questions

1. **좌측 단계 네비를 넣을 것인가.** D3에서 "스타일만 교체"를 골랐으므로 현재 상단 탭을
   유지하는 게 원칙이다. 다만 `.tabs` 를 `flex-direction: column` + 그리드 배치로 좌측
   레일로 옮기는 건 CSS만으로 가능하다. 4~5번 단계를 마치고 시간이 남으면 검토.
2. **시연에 쓸 공고를 정했는가.** 중복 통합은 999건 중 30건뿐이라, 통합 배지를
   보여주려면 그 30건 중 하나를 골라 시연 시나리오를 고정해야 한다.
3. **소비처가 아직 없는 토큰 6개.** `--accent-text`, `--text-title`,
   `--ok-border`, `--no-border`, `--chk-border`, `--pending-border` 는 현재 CSS에
   대응하는 규칙이 없다. 배지에 보더를 넣기로 하면 뒤 4개가 소비되고, 안 넣으면
   지운다. ②를 쓰는 3번 단계에서 결정한다.

## What I noticed about how you think

- 팔레트를 넘기면서 "확인해볼래?"라고 했다. 대부분은 예뻐 보이면 그냥 쓴다. 그 한마디

- "어떤 부분은 도입할 수 없는지를 판별하는 일이 중요해" — 목업을 정답으로 두지 않고

  금액 필드가 없다는 걸 여기서 찾았고, 안 찾았으면 카드에서 제일 눈에 띄는 자리를

- D5에서 내 권장(C)을 안 따랐다. D3에서 "스타일만 교체"를 골라놓고 `app.js` 를 건드리는

  일관된 판단이다. 이유를 설명 안 하고 그냥 고른 것도 나쁘지 않다.
