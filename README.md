# 정부지원사업 공고 자동 분석 · 신청서 초안 생성

「2026 전남광주 청년(Youth) AI 솔버톤」 **트랙 B-08** 과제 구현.

기업마당·K-Startup에 흩어진 정부지원사업 공고를 오픈API로 모아 **중복을 통합**하고,
회사 프로필과 대조해 요건별 **가능 / 불가 / 확인필요**를 판정하며, **신청서 초안 생성과
제출 전 점검**까지 해 주는 웹 도구입니다.

> **해결하려는 문제** — 전자부품 제조업 / 10인 미만 / 스마트시스템 미도입 기업의 경영기획
> 담당자 1인이 매일 여러 기관을 확인해 지원금액·자격·마감일을 엑셀에 수기로 정리하고,
> 공고별 양식에 맞춰 신청서를 반복 작성합니다. **건당 2~4시간**이 들고, 서류 누락·일정
> 착오·문서 간 수치 불일치 위험이 담당자 한 사람에게 몰려 있습니다.

## 빠르게 실행하기

Python 3.10 이상만 있으면 됩니다. **설치할 패키지가 없습니다**(전부 표준 라이브러리).

```bash
python -m tools.seed_dummy      # 연습용 데이터 생성 (최초 1회)
python -m tools.ingest --offline  # 공고 적재 + 중복 통합
python serve.py                 # http://localhost:8000
```

서버는 IPv4(`127.0.0.1`)와 IPv6(`::1`) **양쪽**에 붙습니다. 윈도우에서 `localhost`는
IPv6로 먼저 해석되는데 한쪽에만 붙여 두면 "서버는 떠 있는데 브라우저에서만 안 열리는"
상황이 생기기 때문입니다. 그래도 안 열리면 `http://127.0.0.1:8000` 을 써 보세요.

CLI로 전 과정을 한 번에 보려면:

```bash
python demo.py
```

성능을 숫자로 확인하려면:

```bash
python score.py
```

| 파일 | 키 | 발급처 |

환경변수 `CLOVA_API_KEY` / `BIZINFO_KEY` / `DATA_GO_KR_KEY` 로도 넣을 수 있습니다.

> 공공데이터포털은 같은 키를 Encoding형·Decoding형 두 가지로 보여줍니다. 우리에게
> 필요한 건 Decoding 키인데, 화면에서 둘이 나란히 붙어 있어 Encoding 키를 넣기
> 쉽습니다(그러면 `%2B`가 `%252B`로 이중 인코딩돼서 키가 멀쩡한데도 403
> `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`가 납니다). **어느 쪽을 넣어도 되도록
> `tools/keys.py`가 알아서 되돌립니다.**

키를 넣은 뒤:

```bash
python -m tools.ingest --dry-run   # 응답 원본 필드명 확인
```


### ⓪ 공고 첨부파일 — `tools/bizinfo_client.py`

기업마당은 첨부를 두 쌍으로 줍니다. **신청서 서식을 받으러 공고 사이트를 다시 찾아갈
필요가 없다**는 게 실무에서 큰 차이입니다.

| 필드 | 내용 | 실측 |
|---|---|---|
| `fileNm` / `flpthNm` | 신청서 **서식** (한글 양식 등) | 388/500건 |
| `printFileNm` / `printFlpthNm` | **공고문** 본문 파일 | 500/500건 |

한 공고에 파일이 여러 개면 이름도 경로도 `@`로 이어 붙여 한 문자열로 옵니다(388건 중
171건). 같은 자리끼리 짝지어야 이름과 링크가 어긋나지 않습니다.

링크는 GET에 `Content-Disposition: attachment` 로 파일을 그대로 내려주므로, 화면에서
누르면 바로 저장됩니다. (`HEAD` 요청은 403으로 막혀 있어 링크 검증에 쓸 수 없습니다 —
GET으로 확인해야 합니다.) 초안 탭에는 **서식 파일만** 따로 띄워, 만든 초안을 옮겨 담을
대상을 바로 옆에 둡니다. K-Startup은 첨부를 제공하지 않고 웹페이지 URL만 줍니다.

### ① 중복 통합 — `tools/dedupe.py`

같은 사업이 두 기관에 다른 제목으로 올라옵니다.

```
기업마당  : 2026년 광주광역시 중소기업 스마트공장 구축지원사업 모집공고(1차)
K-Startup : [광주] 중소기업 스마트공장 구축 지원 참여기업 모집
```

세 단계로 좁힙니다.

1. **정규화** — 괄호·연도·차수·상용어(`모집공고`, `참여기업`, `지원사업`…)를 걷어내고
   공백을 없애 '사업의 알맹이'만 남깁니다.
2. **블로킹** — 마감일 ±3일 이내이고 서로 다른 기관에서 온 쌍만 후보로 봅니다.
   같은 기관 안의 1차/2차 공고는 정상적으로 별개 사업이므로 비교하지 않습니다.
3. **유사도** — `difflib` + 토큰 자카드 + **containment**를 5.5:2:2.5로 섞습니다.
   containment 비중이 가장 큰 이유는 교차 게시된 공고가 보통 한쪽이 더 길기 때문입니다
   (짧은 쪽이 긴 쪽에 얼마나 들어 있나를 봅니다).
   **0.85 이상은 자동 통합**, **0.55 미만은 분리**, 그 사이 경계 구간만 하이퍼클로바X에
   "같은 사업인가?"를 물어봅니다.

경계 구간에만 LLM을 쓰는 이유: 전부 맡기면 느리고 비싸며, 무엇보다 매번 결과가 흔들려
재현이 안 됩니다. 확실한 건 코드가 정하고 애매한 것만 물어봅니다.

### ② 자격 판정 — `agent/eligibility.py`

**LLM에게 최종 판정을 맡기지 않습니다.**

```
1단계 (LLM)    공고문 → 구조화된 요건 {축, 연산자, 값, 공고문 원문 인용}
2단계 (파이썬)  요건 + 회사 프로필 → 요건별 가능/불가/확인필요
```

"업력 7년 미만"과 "설립일 2019-03-11"을 비교하는 건 뺄셈입니다. 뺄셈을 LLM에게 시키면
대체로 맞지만 가끔 틀리고, 같은 질문에 같은 답을 준다는 보장이 없습니다. 지원 자격은
틀리면 담당자가 헛수고를 하거나 기회를 놓치는 문제라 재현 가능한 쪽이 옳습니다. LLM은
자유 문장을 구조로 바꾸는 일만 맡고, **판단은 코드가 합니다.**

**근거 없는 요건은 버립니다.** LLM이 뽑은 요건에는 공고문 원문 인용이 반드시 붙어야
하고, 그 문장이 실제로 공고문에 있는지 코드가 대조합니다. 없으면 지어낸 것으로 보고
폐기합니다. 화면의 판정표에 인용이 항상 함께 뜨는 이유이기도 합니다 — 담당자가 5초 만에
'이 판정이 맞나'를 직접 확인할 수 있어야 합니다.

**종합 판정** — 불가가 하나라도 있으면 불가 → 없고 확인필요가 있으면 확인필요 →
전부 통과면 가능. 요건을 하나도 못 뽑았으면 '가능'이라 단정할 근거가 없으므로 확인필요.

**중복 통합의 실익이 여기서 회수됩니다.** 기업마당 공고에는 없는 '신청 제외대상'이
K-Startup 쪽에만 적혀 있는 일이 흔한데, 통합된 공고는 양쪽 원문을 함께 읽어 판정합니다.

### ③ 신청서 초안 — `agent/drafter.py` · `agent/formspec.py` · `tools/formdoc.py`

**항목을 첨부된 신청서 서식에 맞춥니다.** 초안을 잘 써 줘도 항목이 서식과 다르면
담당자가 서식을 따로 열어 옮겨 적어야 합니다. 그 왕복을 없애는 게 목적입니다.

`tools/formdoc.py`가 서식 첨부를 내려받아 글자를 뽑습니다 — **표준 라이브러리만으로**:

| 형식 | 방법 |
|---|---|
| `.hwpx` `.docx` | ZIP + XML. 문단(`<hp:p>`/`<w:p>`) 단위로 끊어 줄을 살립니다 |
| `.hwp` | OLE 복합문서를 직접 파싱(`_CFB`). 파이썬에 OLE 리더가 없고 pip 설치를 안 하기로 했으므로, 스트림 하나 꺼내는 데 필요한 만큼만 구현했습니다. 본문은 zlib 압축이라 풀어서 레코드(`HWPTAG_PARA_TEXT`)를 훑습니다 |
| `.zip` | 안을 풀어 한 단계만 재귀 |
| `.pdf` | **미지원** — 라이브러리 없이 신뢰할 만한 추출이 어렵습니다 |

> **HWP 파싱에서 걸린 함정.** 스펙이 제어문자를 'inline'(4~9,19,20)과
> 'extended'로 나누는데, 'inline'은 크기가 아니라 *본문 흐름 안에 놓인다*는 뜻이라
> **둘 다 8워드(16바이트)를 차지합니다.** inline을 1워드로 처리했더니 뒤따르는
> 파라미터를 글자로 읽어 `…필수 첨부 浥%！ÿ` 같은 깨진 꼬리가 붙었습니다.

`agent/formspec.py`가 그 글자를 세 갈래로 정리합니다(LLM 구조화 + 규칙 폴백):

- **작성 항목** — 문단을 써야 하는 것. 초안의 항목이 됩니다
- **기입란** — 값만 채우는 칸(회사명·사업자등록번호…). 초안에 문단을 쓰지 않고 목록으로만 안내
- **제출서류** — 서식이 함께 내라고 요구하는 서류. ④ 점검에 합쳐집니다

실측: 서식 첨부가 있는 공고 380건 중 **351건(92%)**을 열었습니다(나머지 29건은 PDF 서식).

과거 신청서(`data/past_applications/`)에서 항목별로 비슷한 문항을 찾아
(`tools/past_search.py`, TF-IDF 방식) 그 항목에 맞춰 초안을 씁니다.

**숫자는 AI가 만들지 않습니다.** 매출액·인원 수·설립연도가 필요한 자리에는
`{{매출액}}` 같은 자리표시자만 쓰게 하고, 생성 후 파이썬이 회사 프로필의 실제 값으로
바꿔 넣습니다. 프로필에 없는 값은 `[확인 필요: …]` 로 남깁니다 — 비어 있는 건 눈에
띄지만, 틀린 숫자는 안 띕니다.

### ④ 제출 전 점검 — `agent/checker.py`

문제 정의가 지목한 리스크를 그대로 겨냥합니다. 전부 **규칙 기반**입니다(빠르고 재현 가능).

- **누락 서류** — 공고 제출서류 vs 보유 서류 대조. 표기 흔들림(`등기사항전부증명서`
  ↔ `법인등기부등본`)을 표준명으로 맞춘 뒤 비교하고, 이번에 새로 쓰는 서류(신청서·
  사업계획서)는 누락이 아니라 '작성 대상'으로 구분합니다.

  > **오픈API만으로는 서류 목록을 알 수 없습니다.** 기업마당의 `reqstMthPapersCn`는
  > 필드 이름과 달리 제출서류 목록이 아니라 **접수처·이메일 안내문**입니다(552건
  > 확인, 서류 낱말이 든 것조차 27건). 그래서 ③에서 **첨부 서식을 열어 뽑아낸
  > 제출서류 목록**을 여기에 합칩니다 — 실제로 `【서식 1】 사업 참여신청서`,
  > `개인정보 수집·이용 동의서` 같은 목록이 서식 안에 들어 있습니다.
  > 그래도 목록을 못 얻으면(PDF 서식 등) 없는 목록을 지어내지 않고, ① 어느 첨부를
  > 보면 되는지 파일명으로 안내하고 ② 어느 사업에나 요구되는 **기본 서류**
  > (사업자등록증·납세증명서·중소기업확인서·재무제표)를 대신 점검합니다.
  > 마감 직전에 발급받으러 뛰는 걸 막는 게 이 점검의 실제 값어치입니다.
- **수치 불일치** — 본문의 상시근로자·매출액·설립연도를 프로필과 대조합니다.
- **표기 오류** — 회사명 표기 흔들림, 중복 공백, 반복 문장부호, 닫히지 않은 괄호.
- **일정** — 마감 지남 / 마감 임박(D-3 이내) / 마감일 미상.

## 성능

| | 하이퍼클로바X 사용 | 키 없이 규칙만 (폴백) |
|---|---|---|
| **① 중복 제거** (정답셋 63쌍) | precision 1.000 · recall 1.000 · F1 1.000 | precision 1.000 · recall 0.750 |
| **② 자격 판정** (정답셋 12건) | 정확도 1.000 (12/12) | 정확도 0.833 (10/12) |
| **위양성** (불가·확인필요 → '가능') | **0건** | **0건** |

`python score.py` 로 언제든 다시 잽니다.

폴백 모드에서 떨어지는 두 지점은 예상된 것이고, **떨어지는 방향이 안전합니다.**
중복은 제목 어순이 크게 다른 한 쌍을 놓치고(합치지 말아야 할 것을 합치지는 않음),
판정은 '가능'을 '확인필요'로 미룹니다(신청 못 할 공고를 '가능'이라 하지는 않음).

> **정직하게 밝힙니다.** 위 수치는 `tools/seed_dummy.py`가 만든 **연습용 정답셋**으로
> 잰 것입니다(공고 16건, 중복쌍 63개). 실제 공고는 문장이 훨씬 지저분하므로 이 수치가
> 그대로 나오지는 않습니다. 이 정답셋의 역할은 "완벽함의 증명"이 아니라 **회귀 방지**
> 입니다 — 실제로 이 채점 덕분에 개발 중 여러 판정 버그를 잡았습니다. 예를 들어
> "총 사업비의 50% 이내"라는 지원 조건의 숫자를 인원 요건으로 잘못 읽어 판정이
> 뒤집히던 문제, "체납 중인 기업은 제외" 를 이중 부정으로 처리해 결과가 반대로
> 나오던 문제가 이 채점에서 드러났습니다.
> 인증키를 넣고 실제 공고를 수집한 뒤, 라벨을 추가해 다시 재는 것을 권합니다.
>
> 채점에서 **위양성**(불가·확인필요인데 '가능'이라 답한 건수)을 따로 뽑는 이유는,
> 담당자가 쓸 수 없는 공고에 서류를 준비하게 만드는 가장 비싼 실수이기 때문입니다.

---

## 오프라인에서도 동작합니다

본선 현장에서 네트워크나 인증키에 문제가 생겨도 데모가 멈추지 않게 설계했습니다.

| 상황 | 동작 |
|---|---|
| 한 기관 API 실패 | 다른 기관 것만으로 계속 진행 |
| 두 기관 모두 실패 | `data/notices_cache.json`(마지막 성공분)으로 폴백 |
| 하이퍼클로바X 없음 | 정규식 규칙으로 요건 추출, 중복은 점수만으로 판정 |
| LLM 호출 실패 | 초안은 뼈대 문장으로 대체, 점검은 원래 규칙 기반이라 영향 없음 |

키 파일을 전부 비우고 `python demo.py` 를 실행하면 이 경로를 확인할 수 있습니다.

## 폴더 구조

```
gov-support-agent/
├─ serve.py                 웹 서버 (http.server) + JSON API
├─ demo.py                  CLI 전 과정 시연
├─ score.py                 중복 제거 · 자격 판정 채점
├─ agent/
│  ├─ schemas.py            공용 데이터 형태 (Notice, Requirement, Draft …)
│  ├─ eligibility.py        요건 추출(LLM) + 룰 판정          ← 핵심 난이도 ②
│  ├─ formspec.py           첨부 서식 → 작성 항목·기입란·제출서류
│  ├─ drafter.py            신청서 초안 (항목은 서식에 맞춤, 수치는 자리표시자 치환)
│  ├─ checker.py            제출 전 점검 (규칙 기반)
│  └─ orchestrator.py       파이프라인 조립 + 캐시
├─ tools/
│  ├─ bizinfo_client.py     기업마당 오픈API 어댑터
│  ├─ kstartup_client.py    K-Startup 오픈API 어댑터
│  ├─ dedupe.py             중복 공고 통합                    ← 핵심 난이도 ①
│  ├─ formdoc.py            첨부 파일 열기 (hwp/hwpx/docx/zip, 표준 라이브러리만)
│  ├─ past_search.py        과거 신청서 검색 (TF-IDF)
│  ├─ store.py              SQLite 저장소
│  ├─ ingest.py             수집 잡
│  ├─ seed_dummy.py         연습용 데이터·정답셋 생성
│  ├─ profile_store.py      회사 프로필 + 캐시 무효화 해시
│  ├─ keys.py / apiutil.py  인증키 로딩 / API 공통 부품
│  └─ hyperclova_api.py     하이퍼클로바X 호출 (Structured Outputs)
├─ web/                     index.html · app.js · style.css (3탭 화면)
└─ data/
   ├─ golden_notices.json   연습용 더미 공고 (정답셋과 짝) — 실수집으로 덮어쓰지 않음
   ├─ notices_cache.json    마지막 실수집 결과 (오프라인 폴백용)
   ├─ golden_dupe.csv       중복 정답셋 · golden_eligibility.csv  판정 정답셋
   ├─ company_profile.json  회사 프로필 · past_applications/  과거 신청서
```

> `golden_notices.json`과 `notices_cache.json`을 분리한 이유: 한 파일을 쓰면 실제 공고를
> 한 번 수집하는 순간 더미가 사라져 `score.py`가 채점할 대상을 잃습니다. 회귀 방지
> 장치를 실수로 없애지 않으려고 갈라 두었습니다.

## 화면

| 탭 | 하는 일 |
|---|---|
| **① 공고함** | 마감 D-day 순 목록. 중복 통합된 공고는 **사업 단위로 한 장만** 뜨고 `기업마당 · K-Startup 통합` 배지가 붙습니다. 지역·마감·판정으로 거를 수 있습니다. |
| **② 자격 판정** | 요건별 표 — 요건 / 우리 회사 값 / 판정 / **공고문 원문 인용**. 제출서류·신청 일정과 함께 **공고 첨부파일**(서식·공고문)을 눌러 받을 수 있습니다. |
| **③ 초안 · 점검** | **첨부 서식에서 읽어낸 항목 그대로** 초안을 만듭니다. 상단에 서식 파일 링크와 '값만 채우면 되는 칸' 목록을 띄워, 서식을 열었을 때 뭘 채워야 하는지 미리 보여줍니다. 화면에서 고친 내용 그대로 점검하고, 전체 복사도 됩니다. |
| **회사 프로필** | 판정의 기준값. 저장하면 이전 판정 캐시가 자동으로 무효가 되어 다시 계산됩니다. |

**API 키는 브라우저로 절대 내려보내지 않습니다.** 오픈API·하이퍼클로바X 호출은 전부
서버가 대신하고, 키는 서버 쪽 파일(또는 환경변수)에만 존재합니다.

## 과제 규칙 준수

- 공고 수집은 **공식 오픈API로만** 합니다. 기관 누리집 직접 크롤링 코드는 없습니다.
- 더미데이터(회사 프로필·공고문 캐시·과거 신청서)는 문제 정의가 명시적으로 허용한
  범위에서만 씁니다. `tools/seed_dummy.py`가 만드는 공고는 실존 공고가 아니라, 교차
  게시·표기 흔들림·요건 유형을 재현하려고 지어낸 연습용 데이터입니다.
